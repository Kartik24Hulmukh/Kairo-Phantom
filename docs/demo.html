See the receipt trust model work. In your browser. Right now.

This page generates a real Ed25519 keypair in your browser (WebCrypto — nothing leaves this page), simulates a legal-redline session that emits hash-chained receipts, signs each one, and lets you tamper with a receipt to watch verification fail. This is the same trust model Kairo Phantom uses.

What this is and is not: this is an illustrative, in-browser demonstration of the receipt scheme (Ed25519 signatures over hash-chained JSON receipts). It is not the Kairo Phantom agent itself — the agent is a desktop application. The redline actions below are scripted for the demo. The cryptography, however, is real: real keys, real signatures, real verification, generated live on your machine.
Your browser does not support Ed25519 in WebCrypto. Try a recent version of Chrome, Firefox, or Safari — or verify the same property from the repo with python tools/verify_receipts_external.py demo_output/audit_log.json.

01Generate a signing key

Kairo Phantom holds a local Ed25519 signing key. Here, your browser generates one. The private key never leaves this page.


    


    

      
02Run the redline session

      

        A simulated redline of an indemnification clause: open the document, insert a tracked change,
        save. Each step emits a receipt whose chain_prev is the SHA-256 hash of the previous
        receipt, then signs the receipt bytes with the key from step 01.
      

      

        
      

      

    


    

      
03Verify the chain

      
Verification checks two things: every signature is valid under the public key, and every chain_prev matches the hash of the previous receipt.

      

        
      

      

    


    

      
04Now tamper with it

      

        Flip one byte: change the redlined liability cap in receipt #2 from “12 months” to
        “24 months” after signing — the kind of edit a bad actor would want to hide. Then verify again.
      

      

        
        
        
      

      

    


    

      That full round-trip — sign → verify → tamper → DETECTED →
      revert → verify — is what the repository's tamper-detection tests exercise
      (pytest tests/test_canary_break.py, 17 tests), and any third party can re-verify a real
      audit log independently with python tools/verify_receipts_external.py demo_output/audit_log.json.
